# BizRadar 기술이전 마케팅 기업 발굴 API (초안)

첨부된 카드형 UI에서 필요한 기업 인텔리전스 데이터를 제공하기 위한 백엔드 초안입니다.

## 이번 고도화 범위

1. **기업 기본정보 레이어 통합**
   - Open DART + 금융위(기업기본정보) 데이터를 `corp_no`(법인번호)로 조인
   - 단일 응답에서 재무 정보 + 계열 구조를 함께 제공
2. **KIPRIS 특허 조회 연동**
   - 기업명 기준 특허 보유 현황 조회
   - 등록/소멸 상태 및 상위 기술분류(IPC major) 요약 제공

## API


### `GET /api/v1/companies/search?query={기업명}&limit=20`

기업명 입력 기반 자동완성/검색용 API입니다. Open DART 기업코드 목록(`corpCode.xml`)을 기반으로 회사명을 검색해 `corp_code`를 반환합니다.

응답 예시:

```json
{
  "query": "테스트",
  "count": 2,
  "items": [
    {"corp_name": "테스트기업", "corp_code": "00126380", "stock_code": "123456", "modify_date": "20260102"}
  ]
}
```

### `GET /api/v1/companies/{corp_no}/intel?corp_code={dart_corp_code}`

- `corp_code`를 모를 경우 `company_name` 파라미터를 사용하면 서버에서 기업명으로 `corp_code`를 자동 해석합니다.

응답 예시:

```json
{
  "profile": {
    "corp_no": "110111-1234567",
    "corp_name": "예시테크",
    "financials": [
      {"year": 2025, "revenue": 12000000000.0, "operating_profit": 1800000000.0}
    ],
    "affiliates": [
      {"corp_no": "110111-7654321", "corp_name": "예시홀딩스", "relation": "지배회사"}
    ]
  },
  "patents": {
    "total_patents": 18,
    "active_patents": 12,
    "expired_patents": 6,
    "top_technologies": ["G06F", "A61K"]
  },
  "metadata": {
    "join_key": "corp_no",
    "sources": ["OpenDART", "FSC Basic Info", "KIPRIS"]
  }
}
```

## 매출액 기준 기업 선별 (`scripts/screen_revenue.py`)

기첨부 기업의 사업자등록번호 목록에서 **직전연도 매출액 50억 원 이상** 기업을 골라내는 CLI입니다.

### 데이터 흐름과 제약

공공데이터포털 API 세 개를 순차로 씁니다.

| 단계 | API | 입력 키 | 얻는 것 |
| --- | --- | --- | --- |
| 1 | 국세청_사업자등록정보 진위확인 및 상태조회 (`api.odcloud.kr`) | 사업자등록번호 | 계속/휴업/폐업, 과세유형 |
| 2 | 금융위원회_기업기본정보 기업개요조회 (`apis.data.go.kr`) | **기업명** | 법인등록번호(`crno`) |
| 3 | 금융위원회_기업재무정보 요약재무제표 (`apis.data.go.kr`) | **법인등록번호** | 매출액 |

**1단계와 3단계 사이에는 조인 키가 없습니다.** 국세청 API는 사업자등록번호만 받고 법인등록번호를
돌려주지 않으며, 금융위 재무 API는 법인등록번호만 받습니다. 그래서 2단계에서 **기업명**을 다리로
씁니다. 입력 파일에 기업명 컬럼이 있으면 전 과정이 공공데이터포털만으로 자동화됩니다.

이미 법인등록번호를 보유하고 있다면 `--crno-map` CSV로 주입하면 2단계를 건너뛰어 호출량이 줄어듭니다.
둘을 함께 쓰면 CSV에 있는 건은 CSV로, 빠진 건만 기업명으로 조회합니다.

### 동명이인 법인 처리

기업명은 유일하지 않습니다. 잘못 매칭하면 **다른 법인의 매출액을 가져오게 되므로**, 확정 규칙을
엄격하게 두었습니다.

1. 기업개요 응답에 사업자등록번호가 실려 있고 우리 번호와 일치 → 그 후보로 확정 (`matched_by=bizno`)
2. 정규화된 기업명이 **정확히 하나만** 일치 → 그 후보로 확정 (`matched_by=name`)
3. 0건이거나 2건 이상 동명 → **확정하지 않고** 후보를 `note`/`candidates`에 남겨 수동 확인

기업명 정규화는 `주식회사`, `(주)`, `㈜`, `유한회사`, `농업회사법인` 등 법인 형태 표기와 공백·기호를
제거해 비교합니다 (`(주)예시테크` = `주식회사 예시테크` = `예시 테크`).

2번 규칙은 부분일치를 확정으로 받지 않습니다. `예시테크`로 검색해 `예시테크놀로지`만 잡히면
판정 불가로 남깁니다.

### 판정 불가와 기준 미달의 구분

금융위 재무정보는 **외부감사 대상 법인 위주**입니다. 개인사업자와 소규모 법인은 재무 데이터가
없어 `판정 불가`로 남으며, 확인된 `50억 미달`과 별도로 집계됩니다. 미확인을 미달로 뭉개면 대상
기업을 놓치게 되므로 의도적으로 분리했습니다.

### 사용법

```bash
export DATA_GO_KR_API_KEY=<공공데이터포털 Decoding 인증키>

# 0) 응답 필드명·금액 단위를 먼저 확인 (권장)
python scripts/screen_revenue.py probe --corp-name 예시테크 --crno 1101110043221

# 1) 목록 정제 — 네트워크 없이 즉시 실행. 중복·이상값 제거 후 통계 출력
python scripts/screen_revenue.py normalize data/companies.tsv

# 2) 국세청 상태조회 — 폐업·휴업·간이과세자 사전 제거 (100건 단위 배치)
python scripts/screen_revenue.py status data/companies.tsv -o out/status.csv

# 3) 법인등록번호가 비어 있는 기업만 기업명으로 보충. 한 번 만들어 재사용
python scripts/screen_revenue.py resolve data/companies.tsv -o data/crno_map.csv

# 4) 매출액 조회 후 최종 선별
python scripts/screen_revenue.py screen data/companies.tsv \
    --crno-map data/crno_map.csv --biz-year 2025 -o out/qualified.csv
```

`resolve`를 건너뛰고 `screen`만 실행해도 됩니다. 이 경우 부족한 매핑을 매 실행마다 다시 조회합니다.

주요 옵션: `--threshold`(기본 5,000,000,000), `--biz-year`(기본 2025), `--no-fallback`(직전연도
데이터가 없을 때 전년도로 대체하지 않음), `--no-name-lookup`(기업명 조회 없이 보유 매핑만 사용),
`--sleep`(호출 간 대기, 트래픽 제한 회피), `--limit`(앞 N건만 조회), `--include-all`(미달·불가 건도
CSV에 포함), `--refresh`(`resolve`에서 이미 확보된 법인등록번호도 다시 조회).

### 입력 파일 형식

`업체명 / 사업자번호 / 법인등록번호` 컬럼을 가진 CSV 또는 TSV **한 장**이면 됩니다.
헤더 이름은 부분 일치로 찾으므로 아래 표기가 모두 인식됩니다.

| 필드 | 인식되는 헤더 |
| --- | --- |
| 사업자등록번호 | `사업자번호`, `사업자등록번호`, `brn`, `bizno` |
| 기업명 | `업체명`, `기업명`, `회사명`, `상호`, `corp_name` |
| 법인등록번호 | `법인등록번호`, `법인번호`, `crno`, `jurir_no` |

괄호 주석은 무시하므로 `업체명(마스터 데이터)`, `법인등록번호(마스터 데이터)`도 그대로 됩니다.
컬럼 순서는 상관없고, 헤더를 못 찾으면 `사업자등록번호, 기업명` 2열로 간주합니다.

```tsv
업체명(마스터 데이터)	사업자번호	법인등록번호(마스터 데이터)
주식회사엔그린	120-86-49766	110111-2727472
경상국립대학교	613-83-00570
```

법인등록번호 칸이 비어 있어도 됩니다. 그 기업만 기업명으로 조회해 보충합니다.
같은 기업이 여러 번 나오면 기업명은 첫 행, 법인등록번호는 값이 채워진 첫 행에서 가져옵니다.

`--crno-map`으로 별도 매핑 파일을 추가할 수도 있습니다(같은 헤더 규칙).

### ⚠️ 법인등록번호 칸의 주민등록번호

개인사업자 행에서는 법인등록번호 칸에 **주민등록번호**가 들어 있는 경우가 있습니다
(예: `991231-1000007` 형태). 이를 그대로 외부 API로 보내면 개인정보를 유출하게 되므로,
다음 세 조건을 모두 만족하는 값은 **조회에서 자동 제외**하고 건수를 보고합니다.

1. 앞 6자리가 `YYMMDD` 형태의 유효한 날짜
2. 7번째 자리가 1~4 (주민등록번호 성별·세기 구분자 범위)
3. 주민등록번호 검증식 통과

법인등록번호의 앞 6자리는 등기소·법인종류 코드라 `134111`(월 41)처럼 날짜가 될 수 없는 값이
많고 7번째 자리는 보통 0이므로, 세 조건을 겹쳐 오탐을 없앴습니다. 마스터 데이터에서 발견된
것과 같은 구조의 합성 표본은 모두 탐지되고 실제 법인등록번호 7건은 하나도 걸리지 않는 것을
양방향 테스트로 고정했습니다.

의도적으로 포함해야 한다면 `--allow-personal-id`를 쓰되, 개인정보를 외부 API로 전송하는
행위임을 확인하십시오.

테스트에는 실제 개인의 번호를 넣지 않았습니다. 일련번호를 0으로 고정한 합성 표본
(`991231-1000007` 등)으로 같은 구조를 재현합니다. 마스터 데이터 원본은 개인정보를
포함하므로 리포지토리에 커밋하지 마십시오 — `data/`, `out/` 는 `.gitignore` 대상입니다.

### 출력 컬럼

`brn`, `formatted`, `corp_name`, `crno`, `matched_by`, `nts_status`, `tax_type`, `biz_year`,
`revenue_krw`, `revenue_eok`, `meets_threshold`, `note`

`matched_by`는 법인등록번호를 얻은 근거(`bizno` / `name` / `csv`)이므로, 매칭 신뢰도를 사후
검토할 때 사용하십시오.

### 입력 목록 정제 규칙

원본 목록에 섞여 있는 값들을 다음과 같이 처리합니다. 제외 사유별 건수가 집계되어 출력됩니다.

**사업자등록번호 칸**

| 입력 예 | 처리 |
| --- | --- |
| `613-83-00570`, `6138300570` | 정상 → `6138300570` |
| `"\t635-86-03151"`, ` 316-81-18063` | 공백·탭·따옴표 제거 후 정상 |
| `개인`, `확인불가`, `무상`, `개인(이름)` | `NON_BRN_MARKER` |
| `245-96-0120`, `616-81-7013`, `5935900`, `415-291-11745`, `41-636-057-326` | `BAD_LENGTH` |
| `000-00-00000`, `130-00-00000` | `ALL_ZERO` |
| 체크섬 불일치 | `BAD_CHECKSUM` (`--no-checksum`으로 우회 가능) |

사업자등록번호 검증은 국세청 체크섬 규칙(가중치 `1,3,7,1,3,7,1,3,5`)을 사용합니다.
탭을 품은 인용 칸(`"\t635-86-03151"`)은 `csv` 파서로 읽어 컬럼이 밀리지 않게 처리합니다.

**법인등록번호 칸**

| 입력 예 | 처리 |
| --- | --- |
| `110111-2727472`, `1349110103125` | 정상 |
| 빈 칸 | 정상. 기업명으로 조회해 보충 |
| `확인불가`, `무상` | `NON_CRNO_MARKER` |
| `141211-014578`(12자리), `20534372`(8자리) | `BAD_LENGTH` |
| 주민등록번호 형식(`YYMMDD-*`) | `PERSONAL_ID` — 조회 제외 (위 항목 참고) |

사업자등록번호가 무효한 행은 애초에 선별 대상에서 빠지므로, 그 행의 법인등록번호는
조회에 쓰이지 않습니다.

### 조회량 관리

유효 번호 N건에 대한 호출량은 대략 다음과 같습니다.

| 단계 | 호출량 |
| --- | --- |
| 국세청 상태조회 | `ceil(N / 100)` (100건 배치) |
| 기업명 → 법인등록번호 | 최대 N (`--crno-map`으로 채운 만큼 감소, 결과는 프로세스 내 캐시) |
| 매출액 조회 | 최대 2N (직전연도 + 전년도 대체) |

공공데이터포털 개발계정 일 한도(보통 1,000건)를 넘길 수 있습니다. `resolve`로 매핑을 한 번만
만들어 재사용하고, `--limit`으로 나눠 실행하거나 운영계정 상향 승인을 받으십시오.
`--sleep 0.2` 정도를 주면 순간 트래픽 제한을 피할 수 있습니다.

## Vercel 배포 가이드

기존 `404: NOT_FOUND`는 Vercel이 FastAPI 엔트리포인트를 찾지 못해 발생할 수 있습니다. 이를 위해 아래 파일을 추가했습니다.

- `api/index.py`: Vercel Python 런타임용 ASGI entrypoint
- `vercel.json`: 모든 요청을 `api/index.py`로 라우팅

배포 후 확인:

- `/health` 경로에서 `{"status":"ok"}` 응답 확인
- 프로젝트 환경 변수에 아래 키 등록
  - `OPENDART_API_KEY`
  - `FSC_BASIC_INFO_API_KEY`
  - `FSC_BASIC_INFO_API_URL` (옵션)
  - `KIPRIS_API_KEY`
